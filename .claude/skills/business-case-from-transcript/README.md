# business-case-from-transcript

Turns a project scoping or funding discussion into a finished business case Word file. The agent
reads the transcript and any supporting files, then writes a content file. A script places that
content into a blank template by anchors, so the layout is the same every time and every claim
traces to a source. What the sources do not say is marked `TBD` and listed, not guessed.

## Inputs

- The discussion record: a transcript, call notes or raw notes.
- Optional supporting files: PDFs, Word files, decks, email threads.
- A blank template, either your own (`business_case.template` in the pod config) or one
  generated by `scripts/make_template.py`.
- A profile for the template (`business_case.profile`); empty means
  `references/anchors.example.json`.
- `pm-config.yaml` in `pods/pm/` if the project has one, otherwise
  `shared/pm-config.example.yaml`.

## Outputs

- `content.json`: the drafted content, with a `sources` register and a `missing` register.
- A filled `.docx` saved under `output_dir`, ending with `Sources used` and
  `Missing information`.
- The case goes through `deliverable-review`, then to the step named by `approval_gate`.

## Shared files

Files in `shared/` are fallback copies that let this skill run on its own. Your own settings
live in `pods/` and `brand/`; edit those, never the copies.

## What is in the folder

- `SKILL.md`: the method, step by step.
- `scripts/make_template.py`: generates the blank, branded template.
- `scripts/fill_business_case.py`: places content into a template by the profile's anchors.
- `references/anchors.example.json`: the profile for the generated template.
- `examples/transcript-expense-scoping-call.txt`: a scoping call for ACME Co.
- `examples/expected-content.json`: the content the skill should draft from that call.
- `examples/previews/`: a rendered page of the finished case, when present.
- `shared/`: copies of the notes renderer, brand file, writing standard and pod config.

## Example

The transcript of the March 5, 2030 scoping call for the expense system replacement yields
`examples/expected-content.json`. One open point, the subscription price after year three,
becomes a `TBD` with a matching `missing` entry.

## Requirements

The scripts need python-docx. Profile, content and argument checks run without it. If it is
missing, the fill stops and prints `pip install python-docx`; nothing is installed for you.

## Known limit

A team's own template may carry standalone instruction paragraphs that are not placeholders. The
fill leaves them where they are. Remove them from the template before you use it.

Some table shapes are not handled either. Simplify them in the template first:

- Vertically merged rows (`vMerge`): the fill sees each merged cell as its own blank cell.
- Rows wrapped in content controls: the fill does not see them as rows.
- A labeled totals row with no blank row above it: overflow rows land after the totals row.

## Review

The filled case goes through `deliverable-review` before it reaches the operator.
